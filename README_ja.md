<h1 align="center">⌨️ Keyboard Utils</h1>

<p align="center">
  <strong>Chrome のための最小限の Vim 風キーボード操作</strong><br/>
  スクロール、ジャンプ、入力欄へのフォーカス、ヒントによるクリックをホームポジションのまま行える。
</p>

Keyboard Utils は plain JavaScript で書いた Manifest V3 の Chrome 拡張機能である。ビルドは不要で、リポジトリのディレクトリがそのまま拡張機能になる。

## Why Keyboard Utils?

- **目立つ要素を優先するヒント** — 大きく目立つ要素ほど、押しやすい文字でできた短いラベルを付ける。ヒントの対象は枠で囲まれ、ラベルがどの要素を指すかがわかる
- **小さな機能範囲** — コマンドは 10 個で、要求する permission は `storage` だけ
- **邪魔をしない** — 入力欄にフォーカスがある間はキーをそのままページに渡す。URL の正規表現でサイトごとに無効化できる

## 🚀 Quick Start

**前提**：デスクトップ版の Chrome

1. このリポジトリを clone する

   ```bash
   git clone https://github.com/amaya382/chrome-keyboard-utils.git
   ```

2. `chrome://extensions/` を開く
3. 「デベロッパー モード」をオンにする
4. 「パッケージ化されていない拡張機能を読み込む」を押し、clone したディレクトリを選ぶ

導入前から開いていたタブは再読み込みが要る。長めのページを開いて `j` を押し、下にスクロールすれば動いている。

更新するときは `git pull` してから、`chrome://extensions/` の拡張機能カードにある再読み込みボタンを押す。

## 📖 Usage

### スクロール

`h` / `j` / `k` / `l` で、設定したスクロール量だけ左 / 下 / 上 / 右にスクロールする。キーの前に数字を打つとその回数だけ繰り返し、`5j` なら 5 回分スクロールする。`gg` と `G` は最上部と最下部へ移動し、数字は無視する。

内側のペインをスクロールさせる Web アプリのように、ドキュメント自体がスクロールできないページもある。その場合 Keyboard Utils は画面中央の要素から親をたどり、最初に見つかったスクロールできる要素を動かす。

### ヒント

`f` を押すと、画面内のクリックできる要素すべてにラベルが付く。ラベルを打つと、その要素をクリックする。

クリックできる要素の判定は Surfingkeys に合わせている。対象はリンク、ボタン、フォーム部品、操作用の ARIA role (`button`、`link`、`menuitem`、`tab` など) を持つ要素、`onclick` を持つ要素、`cursor: pointer` で描画される要素である。候補が入れ子になっていればヒントは 1 つにまとめる。リンクならリンク自身にヒントを付け、それ以外の入れ物なら内側でいちばん深い候補にヒントを付ける。

ラベルはヒント文字から作り、ヒント文字の並びで前にある文字ほど押しやすいとみなす。大きい要素ほど、前のほうの文字でできた短いラベルを付ける。どのラベルも他のラベルの先頭部分と一致しないので、最後の文字を打った時点で選択が決まる。

ヒントの表示中は次のように操作できる。

- 文字を打つと、打った文字で始まるラベルだけが残る
- `Backspace` で最後に打った文字を取り消す
- `Esc`、スクロール、マウスのクリックでヒントを閉じる

選んだ要素は種類によって扱いが変わる。入力欄はフォーカスし、`<select>` は選択肢の一覧を開く。それ以外の要素にはポインターとマウスの押下イベントを送ってからクリックするので、`mousedown` に反応する Web アプリでも動く。`Shift` を押しながらラベルを打つと、リンクをバックグラウンドの新しいタブで開く。

### 入力欄

`i` で入力欄にフォーカスする。画面内の入力欄が 1 つならそのままフォーカスし、複数あればヒントを出す。画面内に 1 つもなければ、ページ内で最初の入力欄にフォーカスする。

入力欄にフォーカスがある間、Keyboard Utils は `Esc` 以外のキーをすべてページに渡す。`Esc` を押すと入力欄から抜ける。

## ⌨️ Keys

| キー | 動作 |
| --- | --- |
| `h` / `j` / `k` / `l` | 左 / 下 / 上 / 右にスクロール。前に数字を付けられる (例: `5j`) |
| `gg` / `G` | ページの最上部 / 最下部へ移動 |
| `i` | 入力欄にフォーカス。複数見えていればヒントを出す |
| `f` | クリックできる要素にヒントを出し、選んだ要素をクリック。`Shift` を押しながらラベルを打つとリンクをバックグラウンドの新しいタブで開く |
| `Backspace` / `Shift` + `Backspace` | 履歴を戻る / 進む。数字の前置に対応 (例: `3` に続けて `Backspace` で 3 ページ戻る) |
| `Esc` | 入力欄から抜ける。ヒントを閉じる |

`Esc` 以外のキーは設定で変えられる。

## ⚙️ Configuration

拡張機能の「詳細」から「拡張機能のオプション」を開く。

| 設定 | 既定値 | 説明 |
| --- | --- | --- |
| Keys | [Keys](#️-keys) を参照 | コマンドごとのキー列 |
| Hint characters | `asdfgqwertzxcvb` | ヒントのラベルに使う文字。押しやすい順に並べる |
| Scroll step | `60` | `h` / `j` / `k` / `l` 1 回でスクロールするピクセル数 |
| Disabled URLs | (空) | 1 行に 1 つの正規表現。どれか 1 つでもページの URL に一致すると Keyboard Utils を無効にする |

特殊キーは `KeyboardEvent.key` の名前を山括弧で囲んで書く (例: `<Enter>`)。`Shift` 付きは名前の前に `S-` を付ける (例: `<S-Backspace>`)。

次の場合は保存できない。

- キーが空
- あるコマンドのキー列が別のコマンドのキー列の先頭と一致する (`g` と `gg`)
- ヒント文字が 2 種類未満
- 正規表現として解釈できない行がある

設定は `chrome.storage.sync` に保存され、同じ Chrome プロファイルにログインしたすべての端末に同期される。保存した変更は、開いているタブにも再読み込みなしで反映される。

## 🔒 Permissions

- `storage` — 設定の保存と同期
- すべてのサイトへのアクセス — 各ページでキー入力を処理する

## 🔧 Troubleshooting

### ページでキー操作ができない

Chrome は `chrome://` のページと Chrome Web Store では拡張機能を動かさない。それ以外のページなら、導入後にタブを再読み込みしたかと、Disabled URLs にそのページと一致する行がないかを確かめる。

### サイト自身のショートカットとぶつかる

YouTube などのサイトは同じキーを使う。そのサイトの正規表現を Disabled URLs に足す (例: `^https://www\.youtube\.com/`)。

### 埋め込みコンテンツをクリックした後にキー操作ができない

Keyboard Utils はトップレベルのフレームでだけ動く。フォーカスが iframe の中にあるときは、iframe の外をクリックしてページにフォーカスを戻す。

### ヒントが付かない要素がある

Shadow DOM の中の要素はヒントの対象にならない。

## 🧪 Development

| ファイル | 役割 |
| --- | --- |
| `manifest.json` | 拡張機能のマニフェスト |
| `content.js` | 各ページでのキー処理、スクロール、ヒント |
| `settings.js` | 既定の設定と storage 操作。content script と options ページで共有する |
| `options.html` / `options.js` | options ページ |
| `background.js` | リンクを新しいタブで開く |
| `icons/` | 拡張機能のアイコン |

編集したら `chrome://extensions/` の拡張機能カードにある再読み込みボタンを押し、確かめるページも再読み込みする。
